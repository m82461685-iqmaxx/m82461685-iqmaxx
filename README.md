## 🚀 Featured project: Socket

> A full-screen terminal workbench with a **plugin socket**: plug in tools written in Python, Rust, Go or Node, and use them from one interface.

```text
┌──────────────────────────── SOCKET ────────────────────────────┐
│  [Plugins]  [Logs]  [Agents]                     Ctrl+P: palette │
├──────────────┬─────────────────────────────────────────────────┤
│ ▸ code-review│  Plugin: code-review                             │
│ ▸ log-triage │  Status: running                                 │
│ ▸ agent-sbox │  Findings: ...                                   │
│ ▸ my-plugin  │                                                  │
├──────────────┴─────────────────────────────────────────────────┤
│ socket v0.1  │  4 plugins loaded  │  JSON-RPC over stdio        │
└────────────────────────────────────────────────────────────────┘
```

**Design in one glance**

| Part | Idea |
| --- | --- |
| Core | Full-screen TUI host, event loop, plugin manager |
| Plugins | Separate processes, any language, crash-isolated |
| Protocol | Language-neutral JSON-RPC 2.0 over stdin/stdout |
| Manifest | `plugin.toml` with name, runtime, entry, permissions |
| SDKs | Thin libraries so a plugin is just `on_key()` and `render()` |

**Roadmap**

- [ ] MVP: full-screen host + echo plugin
- [ ] Handshake, manifest, plugin discovery
- [ ] Widget tree: text, list, table, input, image
- [ ] Python SDK, then Rust and Node
- [ ] Permissions, timeouts, hot reload
- [ ] `socket install <plugin>`
